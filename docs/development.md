# Разработка

## Запуск

Нужны Python 3.12+ и PostgreSQL (или Docker).

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env          # ENV=dev, база и SECRET_KEY по вкусу
alembic upgrade head
python create_admin.py --username admin --password secret --role admin
uvicorn app.main:app --reload --port 8002
```

Либо всё в контейнерах: `docker compose up -d --build` (локальный
`docker-compose.yml`, публикует 5432 для удобства — в проде другой файл).

`python seed.py` наполняет базу демо-данными: команды, игроки, соревнование,
матчи с протоколами и событиями.

## Версии

Локальный venv может стоять на Python 3.13 и разрешать зависимости иначе, чем
образ. **`requirements.txt` зафиксирован из боевого контейнера**, не из venv.
Обновлять так:

```bash
docker compose run --rm --no-deps --entrypoint "" api pip freeze
```

Одна закреплённая версия важнее прочих: `bcrypt==4.0.1`. `passlib` 1.7.4 (автором
не поддерживается) падает на bcrypt ≥ 4.1 с `AttributeError: module 'bcrypt' has
no attribute '__about__'`. Не поднимать, пока passlib не заменён.

## Тесты

```bash
pytest              # 60 тестов
pytest tests/test_events.py -v
```

`asyncio_mode = auto`, база — временная SQLite через aiosqlite, схема создаётся
`Base.metadata.create_all`. В `conftest.py` включён `PRAGMA foreign_keys=ON` —
без него SQLite молча игнорирует `ON DELETE CASCADE`, и каскады, работающие
в бою, в тестах бы не проверялись. Из этого следует важное: **тесты идут в обход Alembic
и сломанную миграцию не поймают.** Проверять миграции только `alembic upgrade head`
на PostgreSQL.

| Файл | О чём |
|---|---|
| `tests/test_api.py` | публичные ручки, авторизация, протокол через REST |
| `tests/test_admin.py` | вход в админку, формы, ввод протокола |
| `tests/test_events.py` | таймлайн: вывод агрегатов, валидация, порядок, периоды, разбор времени |
| `tests/test_media.py` | загрузка и перекодирование |
| `tests/test_homepage.py` | блоки главной: порядок, лимит, совместимость со старым видом |

## Миграции

```bash
alembic revision --autogenerate -m "описание"
alembic upgrade head
alembic downgrade -1        # обязательно проверить, что откат работает
alembic revision --autogenerate -m tmp   # должна получиться пустой
```

Соглашения:

- **Новая модель обязана попасть в `app/models/__init__.py`** — `alembic/env.py`
  делает `import app.models`, и без импорта автогенерация выдаст `DROP TABLE` на
  живую таблицу.
- Таймстампы — `server_default=sa.text("(CURRENT_TIMESTAMP)")`. Автогенерация
  против PostgreSQL напишет `now()`; привести к общему виду вручную, иначе схема
  на SQLite и в проде разъедутся.
- `downgrade()` пишется полностью, всегда.
- Проверка «пустой автогенерации» после правки моделей — самый дешёвый способ
  убедиться, что код и схема совпадают.

## Стиль

`ruff`, длина строки 100, правила `E,F,I,UP,B`. Комментарии и сообщения об ошибках
**по-русски** — этим и объясняются отключённые `RUF001-003` (ложные срабатывания
на кириллицу). Каталог `alembic` из проверки исключён.

Комментарий пишется там, где код не объясняет сам себя: почему сдвиг на секунду в
расчёте периода, почему `bcrypt` закреплён, почему у прод-compose отдельный файл.
Пересказывать код словами не нужно.

## Ловушки, на которые уже наступали

Дороже всего обошлись не ошибки в коде, а неверная проверка результата.

- **`docker compose exec -T` съедает остаток heredoc-скрипта.** Команда читает тот
  же stdin. Всегда дописывать `</dev/null`, иначе половина скрипта молча исчезает.
- **`PYTHONPATH=/app`** при запуске скриптов внутри контейнера не из `/app`, иначе
  `ModuleNotFoundError: No module named 'app'`.
- **`tail -N` обрезает начало вывода** — именно там обычно и лежит трейсбек. Смотреть
  вывод целиком.
- **`app.routes` не содержит вложенные роутеры**: в этой версии FastAPI включённые
  роутеры остаются объектами `_IncludedRouter`, поэтому проверка «есть ли ручка»
  через `app.routes` даёт пустой список. Смотреть `/openapi.json`.
- **`ss | grep 0.0.0.0` не находит Caddy** — он слушает `*:80` и `*:443`.
- **psql с двойными кавычками внутри двойных кавычек шелла** ломается. Кидать SQL
  файлом через `docker cp`.
- Файлы, скопированные в контейнер под root, потом удалять `docker exec -u 0`.

## Куда добавлять код

| Хочу | Где |
|---|---|
| новую ручку API | `app/api/v1/<домен>.py` + роутер в `app/api/v1/__init__.py` |
| новое поле | модель → миграция → схемы → сервис → шаблон админки |
| новое правило | сервис, не ручка: `app/services/` — единственная точка, куда ходят и API, и админка |
| новый экран админки | `app/admin/router.py` + шаблон в `app/admin/templates/` |
| работу со временем | `app/services/clock.py` — единственное место, знающее форматы |

Логика в ручке — самая частая ошибка в таком проекте: ровно то же действие есть в
админке, и они разъедутся. Ручки остаются тонкими.
