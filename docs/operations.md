# Эксплуатация: правила ведения данных

Договорённости, которые нельзя вывести из кода. Нарушение любой из них портит
данные молча, без ошибок.

## Заявка и протокол

**Заявка соревнования и протокол матча — разные документы. Заявку по протоколу не
правят.**

Номер игрока в протоколе может отличаться от номера в заявке — судья пишет то, что
на майке в этот вечер. Это нормально и исправлять не нужно.

Отсюда два запрета:

- **не менять номера в заявке** по протоколу;
- **не удалять из заявки** игрока, который в ней был изначально, даже если он не
  играл ни одного матча.

Добавить в заявку отсутствующего игрока — можно и нужно, если он появился в
протоколе.

Правило появилось после того, как одиннадцать номеров были «приведены к протоколу»
и это пришлось откатывать по бэкапам. Хронология матча живёт в `game_events` и
`game_player_stats` и не требует правки заявки.

## Ввод протокола

Порядок: счёт → хронология → отметки участия. Подробно — в
[админке](admin.md#протокол-матча). Коротко:

- отмечать «Играл» **у всех** участников: по этим строкам считается число
  проведённых игр;
- голы, передачи и штраф не вводить руками — они выводятся из событий;
- сохранение с пустой хронологией **обнулит** производные цифры матча;
- буллит вносить типом «Буллит» (`shootout_goal`), не обычным голом: иначе сумма
  голевых событий разойдётся со счётом.

После сохранения стоит сверить три числа: сумма голов каждой команды в событиях
против счёта, сумма штрафных минут против бумаги, число строк участия против
списка в протоколе.

## Что считается по-разному

Расхождения ниже — не баги, а разная база расчёта:

- **турнирная таблица** — только регулярка (`stage = matches`) и только матчи с
  двумя заполненными счетами;
- **бомбардиры и личная статистика** — все стадии, включая плей-офф и товарищеские;
- **буллит** в счёт основного времени не идёт, но в личные голы игрока идёт;
- **конец удаления** — номинальный (начало + минуты). Если удаление прервал гол в
  большинстве, фактическое время окончания раньше; отдельного поля для него нет
  осознанно.

## Разбор бумажных протоколов

Часть бумаги в схему не переносится (перечень — в
[админке](admin.md#чего-протокол-не-хранит)). Практика показала, что при вводе с
фотографии надёжнее всего:

1. сначала выписать голы с временами и передачами, отдельно — удаления, отдельно —
   вратарей;
2. сверить количество голов со счётом **до** ввода;
3. пометку «ПБ» у гола на 60:00 читать как буллит;
4. игрока с пометкой «Иг: нет» в состав не вносить;
5. незнакомую фамилию искать по заявке, а не заводить нового игрока: чаще это
   расхождение в написании.

## Массовые правки данных

Порядок, который себя оправдал:

```
бэкап → пробный прогон со сравнением → запись → строгая проверка → повторный
прогон (должен ничего не изменить)
```

- **бэкап перед любой записью**: `/usr/local/bin/tots-backup.sh`;
- писать **через сервисы** (`save_protocol` и прочие), а не прямым SQL — иначе
  валидация и вывод агрегатов не сработают, и данные разойдутся с тем, что сделала
  бы админка;
- проверять по базе, а не по своим записям о том, что было записано;
- откат читать из бэкапа, а не из памяти.

## Диагностика

Проверять в этом порядке — сверху вниз, от общего к частному:

```bash
curl -s https://api.timeofthestars.ru/health         # приложение живо
docker compose ps                                    # оба контейнера healthy
docker compose logs --tail=200 api                   # трейсбек, если есть
journalctl -u caddy -n 100                           # TLS и прокси
dig +trace api.timeofthestars.ru                     # если недоступен снаружи
```

Типовые случаи:

- **502 от Caddy** — контейнер API упал или ещё поднимается (миграции идут до
  старта uvicorn, `start_period` 60 секунд).
- **API в цикле перезапуска** — почти всегда упавшая миграция: `docker compose logs api`
  покажет её первой.
- **Не логинится в админку** — открыто по plain HTTP: cookie помечена `Secure`.
- **Ошибки TLS** — начинать с `dig +trace`, а не с настроек сервера.
- **Загрузка не проходит** — файл больше `MAX_UPLOAD_MB` либо тип не в списке
  разрешённых.
