# Админ-панель

`/admin`, 43 ручки. Серверный рендеринг на Jinja2, вход по cookie-сессии (не JWT).
Стили и немного JS — инлайном в шаблонах, сборки нет.

Сессия подписывается `SECRET_KEY`; в проде cookie помечена `Secure`, поэтому
**по plain HTTP админка не залогинится** — это не баг.

## Экраны

| Раздел | Что можно |
|---|---|
| `/admin` | дашборд: матчи недели, быстрые ссылки |
| `/admin/teams` | список, создание, правка (включая логотип), удаление |
| `/admin/players` | то же для игроков, с фото и пагинацией |
| `/admin/players/{id}/edit` | правка игрока и его моменты голов из видео |
| `/admin/competitions` | список с логотипами, создание, правка, удаление |
| `/admin/competitions/{id}` | сводка, заявка, матчи, таблица |
| `/admin/competitions/{id}/edit` | все параметры: тип, даты, локация, логотип, победитель, флаги показа |
| `/admin/games/{id}/edit` | параметры матча, ссылка на видео, скан протокола |
| `/admin/games/{id}/protocol` | **ввод протокола матча** |
| `/admin/homepage` | блоки главной: до трёх таблиц и сеток в нужном порядке |
| `/admin/users` | пользователи, смена пароля (только для роли `admin`) |

Заявку соревнования можно наполнять по одному игроку или пачкой через модальное
окно, номер правится там же на месте.

## Протокол матча

Главный экран системы. Три блока сверху вниз.

**Счёт.** Два поля и выбор победителя серии буллитов. Счёт вводится **за основное
время**; под ним подсказка «по событиям: X : Y», которая краснеет при расхождении
с хронологией.

**Хронология.** Строки событий: время в `ММ:СС`, тип, команда, игрок, две передачи,
минуты штрафа, момент в видео. Кнопки добавления по типам, удаление строки, сортировка
по времени. Селекты игроков ограничены заявкой выбранной команды и показывают номер
с фамилией.

Время вводится по-человечески: `16:00`, а `1600` или `16` дополняются на месте до
`16:00`. Момент видео принимает и `45:05`, и `45m5s`, и целиком ссылку с `?t=`.
Разбор — `app/services/clock.py`, единственное место, знающее про этот формат.

**Итоги матча.** Командные цифры для карточки на сайте: броски, броски в створ,
вбрасывания и реализация в процентах — по одной колонке на команду. Пустые поля
не сохраняются, матч без этих цифр остаётся без них.

Штрафные минуты в этом блоке **только показываются**: они пересчитываются из
хронологии прямо во время правки. Реализацию сервер не считает — впишите тот
процент, который посчитан у вас.

**Состав по командам.** Отметка «Играл», признак вратаря и вратарские цифры
(пропущенные, броски, минуты). Голы, передачи и штраф здесь **только для чтения**:
они считаются из хронологии и пересчитываются на месте, пока вы правите события.

### Что важно при вводе

- **Отмечайте «Играл» у всех участников.** Число проведённых игр считается по
  количеству этих строк. Того, кто в бумаге помечен «Иг: нет», вносить не надо.
- **Голы, передачи и штраф не вводятся.** Введите события — числа появятся сами.
- **Сохранение без событий обнулит цифры** этого матча: события стали источником
  истины. Если у матча есть счёт, а хронология пуста, это видно по подсказке под счётом.
- **Заявку править не нужно.** Номер в протоколе может не совпадать с номером в
  заявке — см. [эксплуатацию](operations.md#заявка-и-протокол).
- **Ошибка не теряет введённое.** При неверном значении форма возвращается со всеми
  вашими данными и списком проблем сверху, а в базу ничего не пишется.

Момент видео у гола стоит заполнять не только ради таймлайна матча: из этих таймкодов
собирается блок «Моменты из видео» на странице игрока и такой же список в его карточке
на сайте. Гол без таймкода туда не попадёт.

### Чего протокол не хранит

Бумажный лист богаче схемы. Не переносятся: игровая ситуация (графа «ИС»: большинство,
пустые ворота), код нарушения (графа «Пр»), серия буллитов по попыткам (только
победный бросок), нереализованный штрафной бросок, отметки капитана и ассистента,
разбивка счёта по периодам (считается из событий), зрители, время начала и окончания,
тренеры, лучшие игроки матча.

Конец удаления вычисляется как начало плюс минуты. Если удаление прервал гол в
большинстве, API покажет номинальное время окончания, а не фактическое — так решено
осознанно.

## Главный экран

До трёх блоков, каждый — турнирная таблица или сетка плей-офф выбранного
соревнования. Порядок блоков на странице и есть порядок на сайте; пустой слот
пропускается, поэтому «оставить только третий» — это просто очистить первые два.
Заголовок необязателен: пустой означает «показать название соревнования».

Раньше здесь были два переключателя, и главная умела ровно одну таблицу и одну
сетку. Старый фронт продолжает работать: API выводит для него прежние четыре поля
из блоков — см. [API](api.md#главная).

## Устройство кода

`app/admin/router.py` — все обработчики, `app/admin/templates/` — шаблоны,
`app/admin/deps.py` — сессия, рендеринг и фильтр `clock` для шаблонов.

Формы разбираются вручную, без Pydantic-моделей форм. Два соглашения по именам:
`pid-<player_id>-<team_id>` как отметка участия и `stat-<player_id>-<team_id>-<field>`
для вратарских полей; события — индексированные `ev-<i>-<field>`, где индекс просто
метка строки: пропуски в нумерации нормальны, пустые заготовки отбрасываются.

Обработчик протокола при ошибке делает **явный `db.rollback()`** перед перерисовкой
формы. Это обязательно: зависимость `get_session` коммитит при обычном возврате из
ручки, поэтому проглоченное исключение без отката уехало бы в базу.
